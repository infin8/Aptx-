# Threat model and controls
Threats: hostile mirrors, compromised proxy, HTTP response confusion, malicious archive paths, privilege escalation, repo key injection, TOCTOU between plan and execution, symlink attacks, credential leakage, stale locks. Trust only APT verified repository metadata and exact package digest/size; validate 206 Content-Range and identity encoding; no mixing across source identities. Cache filenames derived from digest, open temp with O_EXCL/O_NOFOLLOW where available, atomic rename and permissions 0700 dirs/0600 files. Never pass user strings to shell; sudo -n for noninteractive and explicit auth error; interactive sudo -v may use controlling TTY; minimal allowlisted native commands and sanitized environment. Never use `sudo aptx` for ordinary user flows. sudo/polkit backend choice documented per distro; sudo default. Package operations via apt-get with native locks; no direct protected DB writes. Verify signatures with APT; do not trust arbitrary downloaded .deb based solely on TLS. CI pip-audit/bandit/secret scanning; record findings, do not suppress failures. Host mutations prohibited in tests. Review repo add/key trust scope before execution.
