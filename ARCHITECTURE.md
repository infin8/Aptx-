# Architecture
CLI Typer/Rich and TUI Textual call ApplicationService. ApplicationService calls AptAdapter (python-apt policy, plan, trusted metadata), DownloadManager (Twisted Agent + HTTPConnectionPool, range validation, retries), Scheduler (per-host/per-package/global semaphores, token bucket), StateStore (SQLite WAL), VerifiedCache (SHA256/SHA512), TransactionRunner (sudo execve-style argv with allowlisted operations, apt-get/dpkg native locks), and EventBus (immutable progress events). CLI never imports reactor before install; reactor install occurs in aptx/__main__.py startup. No privileged Python web downloader. Privileged helper never accepts arbitrary command strings. apt-get's verified acquisition remains authoritative where aptx cannot prove trust and compatibility; if integrating downloaded archives with APT is unsafe, use APT native acquisition and report performance limitation rather than bypass checks.

Network: request immutable trusted package URI/hash/size; HEAD optional; Range GET bytes=0-0 capability probe; require 206 and exact Content-Range, stable validator, length and identity encoding; 200 on range => restart single stream; 416 => re-probe; weak/missing validators => disable cross-session chunk reuse unless expected full digest and stable trusted size make it safe; chunk files only assembled within same source identity and validated final hash. On mirror failover discard partial chunks unless identical bytes are independently validated; safest default is discard. fsync temp data before SQLite checkpoint; atomic rename verified blobs. Keep sqlite outside root-owned directories in user cache; secure modes and symlink checks. Avoid blocking reactor on hashing/disk.

Transaction: python-apt resolves and displays plan; after user confirmation and sudo authorization, native apt-get executes requested operation and remains authoritative for download/install/trust/locking. A future optimized aptx-to-APT archive handoff must have an explicit tested trusted-file contract; until then do not claim accelerated installs. Explicitly report which path used. Repository modifications are privileged and require review of source, key fingerprint, suite and signing scope.
